# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Build

Open `OutlookMailSorter.sln` in Visual Studio (2022 recommended) and build with **F6** or via the Build menu. VSTO add-ins cannot be built with `dotnet build` from the command line — the project requires the Visual Studio Office Tools targets (`Microsoft.VisualStudio.Tools.Office.targets`).

Output lands in `bin\Debug\` or `bin\Release\` depending on configuration.

## Formatting / style

The CI style check runs `dotnet format` in whitespace-only mode:

```powershell
dotnet tool restore          # once, restores tools from .config/dotnet-tools.json if present
dotnet format whitespace --verify-no-changes --folder . --verbosity minimal
```

Run this locally before pushing to avoid the `ci-style` check failing. The `.editorconfig` enforces:
- C# files: UTF-8 with BOM (`utf-8-bom`), CRLF, 4-space indentation, trimmed trailing whitespace
- JSON/YAML/Markdown: LF line endings

## Architecture

This is a **VSTO (Visual Studio Tools for Office) Outlook add-in** targeting .NET 4.7.2.

- `ThisAddIn.cs` — the only hand-authored file. Contains the add-in startup/shutdown logic and any mail-sorting behaviour. All new feature code belongs here (or in new `.cs` files added to the project).
- `ThisAddIn.Designer.cs` / `ThisAddIn.Designer.xml` — auto-generated by Visual Studio. Do not edit.
- `Globals` (in `ThisAddIn.Designer.cs`) — static accessor for `ThisAddIn`, `Ribbons`, and `FormRegions`. Access the live Outlook `Application` object via `Globals.ThisAddIn.Application`.

On startup, `ThisAddIn_Startup` shows a message box with the build time (read from the PE header) and optional commit info from `COMMIT_INFO.txt` co-located with the assembly. All startup code must be guarded — exceptions must not crash Outlook.

`Outlook.Application` (the entry point to all Outlook objects) is available via `this.Application` inside `ThisAddIn` or `Globals.ThisAddIn.Application` from anywhere.

## CI workflows

| Workflow | Trigger | What it does |
|---|---|---|
| `ci-smoke` | PR / push to main | Verifies `.sln` and `.csproj` exist |
| `ci-style` | PR / push to main | Runs `dotnet format --verify-no-changes` |
| `merge-pr` | Manual (`workflow_dispatch`) | Squash-merges a PR via GitHub App after approval/mergeability checks |
| `app-commit` | Manual | Pushes a commit to main as the GitHub App bot |

PRs are merged via squash. The `scripts/` directory contains Node.js scripts (`merge-pr.js`, `merge-pr-checks.js`) used by the merge workflow; they require `APP_ID` and `PRIVATE_KEY` secrets configured for the GitHub App.
